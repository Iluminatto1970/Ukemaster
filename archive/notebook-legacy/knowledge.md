# knowledge.md — Ukemaster Pro

## What this is
**Ukemaster Pro** (`ukemaster-pro` v1.0.0): a free Brazilian-Portuguese ukulele chord (cifra) site, monetized via Google AdSense, Monetag, Amazon affiliate links, and an Apoia-se support banner. All user-facing text is **pt-BR**.

This repo holds the **React components + utilities + tests** for that site. There is no bundler/dev-server config here (no Next/Vite); pages and services dirs are empty placeholders. E2E tests assume the site is served at `http://localhost:3000`.

## Key code
- `src/components/` — all React components (plain JS + JSX, PropTypes, Babel):
  - `AdSenseLoader.js` — injects the AdSense script; integrates with Prebid (`window.pbjs`); renders nothing when `pageType === 'listing'`.
  - `MonetagAd.js` — Monetag placeholder ad, also blocked on listing pages.
  - `Listing.js` — chord listing: pagination (15/page), popularity filter (>1000), renders SupportBanner + MonetagAd.
  - `SupportBanner.js` — Apoia-se donation banner.
  - `AffiliateLinks.js` — affiliate product grid (mock product data; would call an affiliate API in production).
- `src/utils/sanitize.js` — `encodeEntities` (XSS escaping) and `isSafeUrl` (blocks `javascript:` / `data:`). **Always route dynamic URLs through `isSafeUrl`.**
- `public/prebid-config.js` — Prebid.js header-bidding config.
- `scripts/audit_urls.js` — generates `scripts/urls_report.json` classifying pages as `low_value` / `high_value` (AdSense compliance audit; currently hardcoded URL list).
- `content/artigos/` — editorial articles in Markdown (e.g. `como-ler-cifras.md`).
- `docs/superpowers/` — design specs and implementation plans (`specs/`, `plans/`, dated `YYYY-MM-DD-name.md`).

## Production site (ukemasterpro.com) — real architecture
The deployed site is a **separate Vite-built SPA** (source NOT in this repo; only this monetization/test repo is versioned). Key facts, discovered from the production bundle and public Supabase REST API (see `docs/diagnostico-busca-2026-09-19.md`):
- Backend: Supabase `https://asvjdjawaenxrlwdyziy.supabase.co`, publishable key `sb_publishable_...` embedded in the bundle; custom thin REST client (`cr/Sa/Lo` fetch wrappers), not supabase-js.
- Table `songs`: **394,313 rows**; IDs are `scraped-<timestamp>-<rand>` (394,309 rows, ordering follows scraping order, not relevance) + 4 manual `song-*` rows. Artist/title accents are inconsistent ("Legiao" vs "Valença").
- Catalog loading: initial batch of **300** songs (`order=id.desc`), "load more" appends **200** per scroll. Search is **client-side only** over those ~500 rows — that is why production search misses almost everything (99.87% of the catalog invisible to the filter).
- Typing in the header search also switches active tab to `musicas` and view to `list` on **every keystroke** (no debounce), remounting the Library — perceived as "page reloads and jumps to top".
- Reference server-side search implementation + tests live in `src/services/search.js` (+ `__tests__`): primary path is the RPC `search_songs` (GIN trigram index + ranking, accent-insensitive, multi-word), with a PostgREST `ilike` fallback.
- **Applied 2026-09-19** on Supabase project `asvjdjawaenxrlwdyziy` (UkemasterPro): extensions `unaccent`+`pg_trgm`, immutable normalization helpers (`ukm_immutable_unaccent`, `ukm_norm`, `ukm_song_search_text`), GIN trigram index on the normalized expression (NOT a generated column — the 685 MB table would require a full rewrite and block the import cron), and RPC `search_songs(q, lim, off)` with ranking. SQL mirrored in `supabase/migrations/20260919120000_ukm_search.sql`. Verified via REST: accent variants and multi-word queries all return correct results using the trigram Bitmap Index Scan.
- **INTEGRATED (same date) in the real app repo**: `~/Documents/Dev/Iluminatto Dev/Sistemas_Dev/UkuMaster` (Vite+React+TS, deploy Vercel). New `src/lib/searchServer.ts` (RPC client, `null` → local fallback) and `src/lib/useServerSearch.ts` (300 ms debounce, last-writer-wins, DB-side pagination via offset, PAGE_SIZE 50). `SongList.tsx` uses server results when the RPC answers for the current term (hero ranking hidden, "Mostrar mais" pages from DB, footer counter uses DB total); local filter kept as fallback. `App.tsx` now switches tab/view only on the FIRST keystroke (the per-keystroke switch caused the Library remount + scroll jump perceived as a page reload). Also fixed a pre-existing TDZ bug there (`isFiltering` read before declaration in `hasMore`). `.env.local` created with public anon credentials (gitignored) to enable local builds. Verified end-to-end against a local production build: RPC POST → 200, Legião/Legiao/Valença variants and Gusttavo Lima all found in the full 394k catalog. Deployment to Vercel still pending (user action).
- AdminPanel's `fetchAllRows` caps at 300 pages × 1000 rows — undercounts the songs table; use `Prefer: count=exact` instead.
- **Accent fixer (2026-09-20)**: script `scripts/fix-accents.js` normalizes inconsistent `title`/`artist` accents using DB-side cluster voting (RPC `search_songs_accents_dry_run`, windowed by id) + per-pair safeguards (`ukm_is_accent_upgrade`: never removes/changes existing accents, never case-only, never NFD/NFC churn, new accented tokens must exist outside the cluster). Dry-run generates a JSON report at repo root (`relatorio-acentos-*.json`) BEFORE any change; `--aplicar` revalidates each row and stamps `accents_fixed_at`. Useful flags: `--campo title|artist`, `--janela N` (window size; halving on timeout), `--limite N` (quick test), `--excluir file.json` (row_ids to skip), `--pendente`, `--retomar`. SQL mirrored in `supabase/migrations/20260920120000_ukm_accent_fixer.sql`. Measured: ~1.3 s per 2k-row window (was 14.6 s before the btree + trigram-lower indexes and per-pair evaluation). Known majority-wins oddities to review in the report: "Meu Ego"→"Meu Égo", "Incerteza"→"Íncerteza" (scraper-error majority; use `--excluir` to skip).
- **Dedupe (2026-09-20)**: script `scripts/dedupe-songs.js` detects duplicate songs by `(ukm_norm(title), ukm_norm(artist))` — accent/case-insensitive. Catalog reality: 394.313 rows but only ~62.545 distinct songs (scrapers reimported everything; e.g. "Friends — Ed Sheeran" ×19; 52.901 duplicate groups, 331.768 rows to remove). The ~25 s full aggregation is MATERIALIZED once into `songs_dedupe_plan` (table; PK `(norm_title, norm_artist)`; RLS read-only for anon) via RPC `songs_dedupe_refresh()` (~30-60 s) — the frozen plan IS the report, and the script just pages it (30 s for all 52.9k groups). Keep criterion: highest votes → views → newest `created_at` → longest title → highest id (deterministic). Flow: `--atualizar` (rebuild plan) → default dry-run writes `relatorio-dedupe-relatorio-*.json` at repo root (resumo + histograma + top-20 groups; with `--limite N` it embeds full group detail) → review → `--aplicar` (requires SUPABASE_SERVICE_ROLE_KEY; revalidates keep/removíveis per group, transfers song_votes to the keeper via on_conflict ignore-duplicates, deletes in batches of 100, idempotent on re-run). Flags: `--atualizar`, `--aplicar`, `--limite N`, `--excluir file.json` (`["<keep_id>"]` or `[{norm_title,norm_artist}]` — skip groups under review), `--retomar` (checkpoint in `scripts/.dedupe-apply-state.json`, invalidated if plan was regenerated). SQL mirrored in `supabase/migrations/20260920130000_ukm_dedupe.sql`; `songs_dedupe_refresh()` execute was revoked from anon/authenticated (service_role only). Import cron will recreate duplicates — refresh + re-apply after big imports.
- **Dedupe APPLY completed 2026-09-20**: 331.768 rows deleted in 11 batches of 5.000 plan groups (exact plan total); `songs` is now 62.545 rows with **0 duplicate groups** (re-verified). `songs_dedupe_plan` kept as audit trail; `songs_dedupe_divergencias_20260920` holds the 14.842 divergent lyric contents (the only non-recoverable data; MD5 + keep reference per row); `song_votes` untouched (0 votes were on removable rows); `ANALYZE songs` run afterwards.
- **Security audit / lockdown (2026-09-20)** — applied live and mirrored in `supabase/migrations/20260920150000_ukm_security_lockdown.sql` (idempotent). Findings fixed: (1) backup table `songs_dedupe_divergencias_20260920` had NO RLS (lyric contents exposed) → RLS on, zero policies (service_role only); (2) eight tables had open `TO public ALL using(true)` policies — anon could INSERT/UPDATE/DELETE certificates, affiliate_links, partner_links, blog_posts, chord_dictionary, cron_imports, cron_log, scrape_state → split into public SELECT + authenticated writes; `cron_log` is authenticated SELECT-only (workers/cron write via service_role); `worker_commands` recreated without anon roles (insert gated to admin e-mail via `auth.jwt()->>'email'`, rest authenticated); (3) admin RPCs (`songs_dedupe_refresh`, `ukm_apply_accent_fixes` both overloads, `search_songs_accents_dry_run`, `songs_dedupe_scan`) — EXECUTE revoked from anon/authenticated **and PUBLIC**: revoking only the roles is NOT enough because the default PUBLIC grant is inherited by both; validate with `has_function_privilege(...)`; (4) TRUNCATE/REFERENCES revoked on all public tables. App preserved: `src/lib/supabase.ts` always sends `Bearer <session JWT || anonKey>` — the admin panel operates as `authenticated`; public surfaces keep anon read. Verified externally via curl: anon blind on internal tables, anon writes 401, `search_songs` still 200 (~0.6 s).
- **Import full-catalog discovery (2026-09-20)**: CifraClub KILLED `/artista/musicas.html` (404 since ~09/2026) and artist roots only SSR ~15-25 songs (rest loads via JS) — that's why imports got stuck at ~50. Fix in `Sistemas_Dev/UkuMaster`: discovery now uses CifraClub's OFFICIAL sitemaps (robots.txt → `gcs/sitemap/sitemap_index.xml` → `sitemap_cifras_1..21.xml.gz`, ~1M song URLs). A generated 3.5 MB embedded index maps 135k artist slugs → sitemap file numbers (`src/data/cifraclubSitemapIndex.ts`, regenerate with `node scripts/rebuild-cifraclub-sitemap-index.mjs`; cache-aware; gzip OR plain xml). `discoverArtistSongLinks` tries sitemap FIRST (cached in `$TMPDIR/cifraclub-sitemaps`, concurrency 3, deadline-aware; partial download returns partial list — re-run to complete) and keeps the HTML flow as fallback. Verified live: Roberto Carlos 616 links (was 24), Alceu Valença 167, end-to-end `scrapeArtistPage` scraped originals + `(Simplificada)` variants. The index is server-side only (cron bundle + server.cjs carry it; the visitor bundle does NOT — verified). Anti-duplicate hardening: (1) `platformCron.fetchAllRows` cap raised 20k → 500k rows for `songs` and `cron_imports` (the 20k cap was the root cause of the 84% duplicate catalog — existing keys beyond it were invisible); (2) UNIQUE partial index `ukm_songs_title_artist_norm_uniq on songs (ukm_norm(title), ukm_norm(artist)) where ukm_norm(title) <> ''` — the DB now rejects duplicates from ANY writer (migration `supabase/migrations/20260920160000_ukm_unique_title_artist.sql` in the app repo); with it, upserts of an existing title+artist under a NEW id return 409, so (3) `cloudSync.adoptExistingSongIdsFromCloud` reconciles imported songs to existing cloud ids before the app's push (import becomes UPDATE, preserving votes; `ukm_norm` = lowercase + NFD-stripped + collapsed spaces — mirrored client-side exactly). Cron/worker must be redeployed with the new `dist-cron/` bundle (npm run build:cron) for full-catalog rounds.
- **Gotcha — Supabase read-only after bulk deletes**: right after the 331k-row delete the DB flipped to `25006 cannot execute ... in a read-only transaction` (`transaction_read_only=on`, disk-full protection; WAL retention 592 MB vs `max_wal_size=1GB`). No `CHECKPOINT` privilege; it self-healed after ~5 min (`checkpoint_timeout`). Expect write-locked windows right after big DELETEs — don't mistake it for a broken migration.

- **Unit/integration (Jest):** live in `src/components/__tests__/` with subfolders `reliability/` and `security/`. Setup: `@testing-library/jest-dom/extend-expect`. `tests/e2e/` is excluded from Jest via `testPathIgnorePatterns`.

## Conventions
- Components: plain function components, **PropTypes declared for every prop**, JSDoc-style header comments, Portuguese identifiers/comments.
- Babel only (`@babel/preset-env` + `preset-react`); no TypeScript.
- New editorial content must be **≥ 300 words of original text** (AdSense policy, see `docs/superpowers/specs/2026-09-14-adsense-compliance-design.md`).

## Hard constraints / gotchas
- **AdSense compliance rule (core business constraint):** NEVER render ads on automatic listing pages. Any ad component must return `null` when `pageType === 'listing'`. Ads only on curated/editorial pages.
- **Placeholders must be replaced before production:** AdSense client `ca-pub-XXXXXXXXXXXXXXXX`, slot `1234567890` (in `AdSenseLoader.js`), and the Monetag script URL `https://cdn.monetag.com/monetag.js`.
- **Known bug in `MonetagAd.js`:** early `return null` for listing pages occurs *before* the `useEffect` call — a Rules-of-Hooks violation that will crash if hooks order changes between renders. Fix when touching that file.
- Dynamic URLs in `Listing.js` fall back to `/cifra/` when `isSafeUrl` rejects them — keep that fallback pattern for new link surfaces.
- Empty top-level dirs (`App/`, `Canal/`, `Marketing/`, `Monetizacao/`, `Produtos/`, `config/`, `doc/`, `resources/`, `workflows/`, `other/`) exist but contain no code — don't assume content there.
